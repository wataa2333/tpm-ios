# Android 更新与批量处理变更记录

> 历史记录：本页0.57.0、bsdiff/bspatch和Commons Compress方案已被后续修改替代。当前为1.58.0（58），只支持全量APK更新；发布按[当前发布说明](自动更新发布说明.md)，最新状态按[交接目录](../docs/handoff/README.md)。下文仅用于追溯，不能当成当前完成状态。

版本配置保留 0.57.0（57）。所有业务流程测试使用本地假响应，没有调用真实受理、审批、维修保存或 ERP 出库接口。

## 自动更新

新增 `update/` 模块，复用协程和 HttpURLConnection，增加 Commons Compress 1.28.0 用于 BSDIFF40 的 BZip2 解压。入口为启动检查和“我的 → 应用更新”。支持进度、暂停/继续、持久断点、三次重试、SHA-256、增量失败回退完整 APK，验证包名、版本、当前签名后调用系统安装器。

发布工具为 `tools/publish_android.py`，自动验证正式签名 APK、生成并回放 BSDIFF40 补丁、生成清单，选择 `--upload` 时通过发布机环境变量读取 COS 凭据；上传数据文件成功后才更新清单。没有向 COS 实际上传，也没有在客户端添加密钥。

完整操作见 [自动更新发布说明](自动更新发布说明.md)。首次启用需要提高版本号，使用原签名覆盖安装一次；之后才能 App 内更新。

## 批量处理

1. 将处理权限、服务端操作分支、下一节点审批人、任务字段校验提前到维修/领料写入之前，避免缺审批人或无权限时已经保存维修结果。
2. 每单重新核对状态和任务，维修记录返回其他任务时阻止继续；网络适配器在请求前后核对账号/厂区，批次循环也固定最初作用域。
3. 受理使用服务端实际提供的 `assign` 或 `appoint` 指派分支。批量方案允许不统一选班组，但每张单据必须有自己的有效班组；选了统一班组则覆盖。原来一条“必须统一选班组”的旧测试已按页面现有规则纠正，增加实际处理时缺班组不能提交的测试。
4. 新建出库明细必须与申请物料逐一对应，按物料 ID 匹配使用数量；缺行、重复、额外行不再默认数量 1 或继续提交。已创建出库单时明确提示核对，避免重复领料。
5. 同样异常的自动选择按异常阶段分类，库存不足的决定不会套到后续创建单据失败等不同问题。
6. 固定读取方案时的选单快照；取消选择或变更所选单据后不会启动旧方案。单据身份包含种类，维修和 ERP 相同编号不会相互取消选中。
7. 校验非有限物料数量、维修花费；批量保存维修结果前复用单张维修表单校验。
8. 维修保存成功但流程提交异常时，明确提示“已保存、流程提交未确认，请刷新核对、勿重复领料”，不会自动重试业务写入。
9. 单张完成页的领料明细新增独立“料号”行，兼容物料位于 `material` 与 `materialOutbound.material` 的响应；批量方案和缺料提示也标识料号。

## 验证与限制

- Android 单元测试：76 项通过，包含 10 项更新测试、12 项新增批量流程测试。批量假响应覆盖权限、审批人、顺序、退单分支、任务变化、班组、指派、物料匹配、编号冲突、部分提交失败。
- Python 发布脚本：6 项离线测试通过；COS 上传顺序与失败保护使用 SDK 替身，没有真实上传。
- Release 压缩构建通过，最终命令用时 54 秒；lint 0 错误、20 条警告（含现有依赖/样式建议与更新缓存空间建议）。完整日志：`build/android-batch-verification.log`。
- 本机未配置正式签名，项目原有 fallback 使用 debug key；生成包仅验证构建，发布脚本实际拒绝这种签名。正式升级必须使用原签名并提高 versionCode。
- 尚未验证真实 COS 下载/Range 响应、不同 Android 厂商安装授权与覆盖安装、升级后数据保留、真机视觉。当前没有连接 Android 设备。
- 后端的“创建 ERP → 保存维修 → 提交流程”是多个独立请求，没有服务端原子事务/幂等接口，客户端不能保证中途失败时自动回滚。需要根据提示刷新核对，不应盲目重试领料。

复验命令（JDK 17）：

```powershell
cd android
./gradlew :app:testDebugUnitTest :app:assembleRelease :app:lintDebug --continue
```

发布脚本测试在安装 `tools/requirements-android-update.txt` 的 Python 环境运行：

```powershell
python -m unittest discover -s tools -p test_publish_android.py -v
```
