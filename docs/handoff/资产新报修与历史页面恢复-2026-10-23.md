# 资产新报修与历史页面恢复

Android源码1.77.0/code77。用户反馈并授权新增资产编码带入报修、修正上次数据展示、趋势顶部控件分区。本轮未编译、运行测试、推送或进行真实业务写入，仍由用户Studio验收。

## 新建报修

- 报修详情底栏在退单/完成任务操作行下方，新增独立整行“使用此资产编码进行新建报修”。即使当前单据无任务操作权限，也可尝试进入全新报修，实际资产读取及提交使用当前登录账号的服务端权限。批量预览不显示该动作。
- 工单查询展开卡片在打开工单按钮下、资产台账展开卡片最底部也提供相同入口。长文字允许换行，不与原操作挤在同一行。
- AppNav通过新表单页面的savedStateHandle传递资产，不放URL，不复制原单其他字段。FaultFormScreen按当前登录账号用assetId查询资产，并核对assetId/assetCode后选中；选择器显示编码与名称。
- 从资产进入的新单不自动加载其他新报修草稿，原草稿仍保留，可手动从草稿箱选择。申请人、默认受理配置和提交权限沿用原新建流程；带入动作不提交、不创建真实单据。资产核对失败提示手选。
- TaskActionBar增加可选导航栏留白参数；ERP调用同步采用命名参数，默认行为保留。

## 上次数据展示修正

- 1.76.0只保存汇总并显示纯文字列表，用户明确要求正常展示页面、仅提示非最新。本版优先于旧交接的“仅保存统计数值”策略。
- 上次人员汇总改回原双列卡片、配色、数量排序；顶部显示上次数据、非最新、查询时间及日期范围。原1.76缓存可直接用既有汇总恢复卡片，无伪造工单。
- 新查询在原SecureFile账号/查询身份/厂区隔离缓存中增加标准化显示快照：分页完整性、人员执行核对结果、工单显示字段和维修结束日期，无服务器原始响应、凭据或工作流提交载荷。
- 新快照可恢复人员工单、曲线及表格，仍明确为旧数据；打开工单后原详情页重新读取并核验实际权限。旧缓存未存工单和趋势，需重新查询一次后才有完整展示。
- 旧分页不能继续或重试，必须重新查询，避免将昨天的偏移与新数据混合。内部返回仍保留本轮数据；明确退出后恢复上次记录；切账号/查询身份/厂区隔离与旧请求丢弃逻辑保留。
- 新增RepairSnapshotCacheTest覆盖快照往返、同名不同账号、分页不完整、日/月趋势及无效缓存，未运行。

## 趋势布局

- 日期范围和查询操作、统计粒度和口径说明、人员对比分别放入独立GroupCard，统一内部留白及区块间距。
- 横屏人员选择的标题和全选/清空区域也单独分组。
- 旧数据趋势页顶部有非最新提示；说明改为待确认、待复线及已完结，仍按repairEndTime。

## 验收重点

1. 当前登录账号与查询账号不同：三个入口资产带入正确，新单无旧单内容、无其他草稿混入；退出/返回、新单草稿保存正常；无权资产不自动使用查询账号提交。
2. 完整和暂停查询分别退出重进，卡片数量、人员身份、日期范围与曲线表格一致；非最新提示清楚，内部往返不变；跨账号和厂区不串数据。
3. 原1.76旧缓存升级后显示人员卡片；首次重新查询后退出重进能查看原图表表格。
4. 竖屏和横屏顶部区块分隔清楚，长按钮/大字体可换行，底部不被系统导航栏遮挡。
