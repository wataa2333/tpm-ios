## 使用方式

App 进程启动时检查一次，不阻塞登录。发现更高 versionCode 时，弹窗先显示版本、更新日志及完整 APK 大小，用户选择下载后才开始下载。我的 → 页面最下方“应用更新” → 检查更新，也会展示日志；即使已是最新版本，仍展示云端发布版本的日志。未填写日志时显示“本版本暂无更新日志”。不提供历史版本日志列表。

保留下载进度、HTTP Range 断点续传、最多 3 次重试、SHA-256/大小/包名/版本/签名校验、系统安装界面。下载在应用级协程中运行，切页不终止；进程结束后需重新进入并继续。系统安装由用户确认，同包名同签名覆盖安装保留原数据。

## 每次发新版

1. 在 android/app/build.gradle.kts 增加 versionCode，修改 versionName。
2. 在 Android Studio 生成使用原 keystore、alias 签名的 release APK。不要使用自动回退 debug key 的包，脚本会拒绝 Android Debug 证书。
3. 将日志写入 UTF-8 文本，例如 D:\releases\更新日志.txt，每行一条。
4. 在项目根目录运行下面的发布脚本。

首次安装发布工具：

```powershell
python -m venv .private/update-venv
.private/update-venv/Scripts/python -m pip install -r tools/requirements-android-update.txt
```

生成发布文件（将 APK 和日志路径换成实际路径，输出目录必须为空）：

```powershell
.private/update-venv/Scripts/python tools/publish_android.py `
  --apk 'D:\releases\新版.apk' `
  --out 'build\publish-new' `
  --notes-file 'D:\releases\更新日志.txt'
```

也可用 `--notes '修复问题与体验改进'` 直接输入日志，与 --notes-file 二选一；最多 8000 个字符。需要 Python 3.10+、Android SDK Build Tools 和可运行 apksigner 的 JDK。SDK 默认在 Windows 常规路径，可指定 --sdk。

输出：

```text
build/publish-new/
  version.json
  release-info.txt
  releases/<versionCode>-<hash前16位>/app.apk
```

## 腾讯云上传

桶 wataa-1259218212，地域 ap-guangzhou。

- 手动上传：先上传 releases 文件夹，保持相对目录结构；APK 完成后最后将 version.json 上传至桶根目录。release-info.txt 无需上传。
- 更新文件应允许公开读取，不开放公共写入。version.json 设置 Cache-Control: no-store, max-age=0。
- 自动上传：在当前发布终端或 CI 的秘密变量中设置 COS_SECRET_ID、COS_SECRET_KEY，临时凭据另设 COS_SESSION_TOKEN，再给生成命令加 --upload，输出目录换一个新的空目录。脚本会先传 APK，最后更新清单，并检查云端版本以防回滚。不要并行发布。
- 密钥不写进项目、日志文件或 APK，不需要发给使用者。
