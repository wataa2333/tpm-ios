# 原生 iOS 单据工作台 0.3

SwiftUI 原生界面，目标 iOS 27。主页、工作台、故障报修、我的四个入口，只有一套底部导航。故障报修按原八状态横向切换，默认待抢单，搜索字段显式选择。报修新建使用右下角独立系统玻璃按钮；表单底部保存左侧浅黄色大图标、提交右侧蓝色大图标，必填项按原包规则标红色星号。

本版重点为报修、自修、ERP 多物料领料和实际流程节点。主页与我的提供厂区切换：读取账号授权厂区，调用原接口取得新令牌，成功后重建页面并刷新数据，丢弃旧厂区未完成的请求结果。外协维修及外协 ERP 申请暂不提供。保养、精密度检查维持演示范围。

正常启动进入原系统登录。报修、资产、库存、ERP 查询和工作流使用原 APK 的服务器接口；保存和提交保留原对象字段、审批人变量及业务参数，状态由服务器返回。没有新增紧急程度字段。维修结果保存后再进入当前审批节点。

ERP 每张单包含多条物料，各自保留批次、子库、货位、单位及数量。每行独立校验库存、重复物料及实发数量。维修领用关联实际出库物料明细。

流程展示读取服务器处理历史及全部配置节点，显示处理人、时间、结果、意见及会签信息；尚无记录的配置节点不代表必经路线。操作入口依据服务器任务和权限展示。

首次加载、刷新、分页、照片上传、保存、提交使用系统 ProgressView；未加载完成、请求失败或提交中不能重复提交。会话保存在设备钥匙串，密码不持久保存。

验证范围：已使用用户本地登录的会话检查只读接口。尚未创建正式报修、提交审批或实际出库，业务写入、真实厂区切换与 iPhone 实机安装仍待验证。构建成功及截图不代表生产全流程验证。

DEBUG 截图入口使用虚构数据，与登录后的真实业务路径隔离。截图不能替代端到端操作测试。数据校验单元测试与 ERP 页面启动检查在模拟器运行。

构建：GitHub Actions 手动触发，使用 xcode-27 标准环境与 XcodeGen。产生未签名 IPA、模拟器截图和测试结果，保留三天。不配置付费服务。

安装：未签名 IPA 需在本地签名后才能安装。Windows Sideloadly 与个人 Apple 账号的签名、刷新和 iOS 27 实机兼容性仍待验证，Apple 登录由用户本地完成。

原 APK、解包资源、账号会话和真实业务快照不上传。最新 APK 地址已记录在本地，下一次业务迭代再比较 MD5、SHA256 与实际改动。
