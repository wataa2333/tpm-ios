共享 InterfaceMotion 在“减少动态效果”开启时返回 nil 动画。原有登录/厂区、列表加载、状态条数字、toast、加载 overlay 等也接入；卡片、按钮、UIKit TabBar/滚动原有减弱处理保留。不能以此代替实际设备的可访问性验收。

额外防竞态：详情每轮读取带 run ID 和 scope 校验，过期响应不更新操作快照；异步维修说明也按同一轮次丢弃旧响应。没有新增业务写接口，OriginalTasks.swift 的业务写请求语句与本轮开始时完全一致。

验证：12 个源文件相对本轮本地基线通过 diff 空白/冲突检查；静态核对业务写调用未变、动画回归示例不调用业务 API。日志 build/ios-animation-static-check.log。Windows 无 swift/xcrun/xcodebuild，未编译，未运行 XCTest，无新 IPA。

新增 DEBUG `--screen motion-regression` 离线场景，使用真实 BatchBar、纯本地选单，运行按钮无业务行为；新增 MotionTests.swift 两个 UI 测试，覆盖普通/减少动态效果下三轮选择取消、操作行可点、取消后高度回到原值。**测试仅新增未执行；测试验证终态尺寸，不证明动画中间帧或详情闪烁已消除。** 不自动启动截图工作流或云构建。

仍需在设备上核对：两个用户反馈路径、取消/提交的关闭顺序、快速连续选择、键盘交互式收起/硬件键盘/横屏、加载首屏和分页、深层返回手势取消、长文本/大字体、减少动态效果。管理看板未实施，仍按前一份交接边界处理。

## 以下为修复前静态排查记录

按用户要求，本轮只统计，等待后续修复指令。范围是 ios/TPM 下所有 Swift 文件的 animation、transition、withAnimation、UIKit 动画、safeAreaInset 和主要条件内容切换。**静态结果不是完整运行验收，也不能仅凭未显式声明动画就断言系统没有动画。** 导航、sheet、DisclosureGroup 等由系统提供过渡；未启动截图工作流、云构建或生产请求。

## 一致性问题

“减少动态效果”已被卡片、部分按钮/状态条及 UIKit TabBar 使用，但 BatchHost、DashboardCard 数字、多个页面 loading/busy、toast、AnimatedLoadingOverlay、键盘行等尚未统一处理。后续应按减少移动、保留必要状态反馈的原则逐项核对，不能把缺少环境变量直接当作已复现的可访问性故障。

下轮建议先处理两个用户已报告的问题，再处理键盘/底部 inset 联动与选择器反馈；本清单所有“疑点”都需要运行验证后才能标为修复完成。
